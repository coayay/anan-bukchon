# 경쟁사 후기 아카이브 — 누적 관리 규칙

안안(가회동 33-20) 경쟁 숙소의 실제 후기를 숙소별 1파일로 누적한다. 이 폴더가 원본이고, 통합 분석은 상위 `research/competitor-review-analysis.md`의 13개 축을 코딩 프레임으로 쓴다.

## 1. 폴더 구조

- `README.md` — 이 문서 (규칙 · 입력 템플릿 · 인덱스)
- `YYYY-MM-DD_숙소명_리스팅ID.md` — 숙소별 정제 원본 + 통계 + 안안 시사점
- `YYYY-MM-DD_숙소명_리스팅ID.csv` — 같은 내용의 표 (노션 DB 임포트용)

날짜는 수집일. 같은 숙소를 다시 수집하면 새 날짜 파일을 만들고 인덱스에 두 줄을 남긴다 (변화 추적).

## 2. 후기 전달 방법 (권장 순서)

1. 에어비앤비 리스팅 → "후기 전체 보기" → 정렬을 **최신순**으로 바꾼 뒤 끝까지 스크롤해 전체를 드래그 복사
2. 메모장(.txt)에 붙여 넣고 맨 위에 아래 헤더 5줄을 쓴다
3. 파일명 `숙소명_YYYYMMDD.txt`로 저장해 Claude에 업로드

헤더 템플릿 (복사해서 사용)

```
한옥명 : 
리스팅 : https://www.airbnb.co.kr/rooms/
후기 수 : 
표시 평점 : 
수집일 · 정렬 : 2026-09-10 · 최신순
```

- 30건 이하 소량은 채팅에 바로 붙여도 된다. 50건 이상은 반드시 .txt 파일로.
- 표시 평점(리스팅 상단 별점)과 세부 평점(청결도·정확성·체크인·의사소통·위치·가격)을 헤더에 적어두면 후기 평균과 비교할 수 있다.
- 자동 번역본이면 그대로 둔다. 원문이 필요하면 "원문 보기"를 누른 상태에서 복사.
- 호스트 답글도 함께 복사한다 (응대 SOP 분석에 쓴다).

## 3. Claude가 하는 일 (파일당)

1. UI 문구 제거 후 후기·답글을 번호·평점·월·프로필 형식으로 정제
2. 후기마다 P/N 코드 부여 (프레임: `../competitor-review-analysis.md` 2·3장 + P0 전반 만족, P8 재방문·추천)
3. 평점 분포·연도별 평균·축별 집계를 스크립트로 계산
4. 안안 시사점 10개 내외 작성 (사실 / 추정 / 확인 필요 구분)
5. .md + .csv 저장, 이 README 인덱스 갱신, 커밋·푸시
